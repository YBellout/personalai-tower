# D-015  The control room is the status dashboard, and the status has one fixed form

    Scope:       control-tower, inherited by every project control room at adoption
    State:       answered
    Decided by:  Yassir, 2026-09-20
    Supersedes:  nothing

## Context

Yassir keeps the control room chat open on the side as his project status dashboard and
asks for the status often. He wants it brief, actionable, simple and visual, telling him
where he is and what he must do next. The Tower will build an HTML UI later.

## Decided

1. The status is regenerated on the word `status` and after every completed work step.
2. It is always read fresh from the hub, per `knowledge/status.md`, never from memory.
3. Two outputs: `status/status.json` as data, and a rendering. Today the rendering is
   the side doc rewritten in place. At M1 the HTML UI reads the same json.
4. Layout is fixed, and Yassir's actions come first.

## Reversibility

Fully reversible. The layout is one file, the data shape is versioned in git.

## Closes when

The M1 UI renders `status.json` and the side doc is retired.
