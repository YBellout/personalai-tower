## Context

Five projects need somewhere to be governed from, and the Tower's own rules have to
live somewhere a chat reads before it acts. claude.ai project instructions are the
only text a session is guaranteed to see, and the Tower cannot edit them.

## Options

1. **Recommended, and taken.** A Tower project plus one project per app, each app
   keeping its own control room chat. The Tower's instructions hold rules only, its
   project knowledge holds pointers, never content.
2. One project for everything, chats separated by naming. Cheapest to set up, and
   every chat then carries every other project's context, which is the cost.
3. One project per app, no Tower project. Nothing then owns a cross-project decision,
   which is the whole reason the Tower exists.

## Reversibility

All three are configuration in claude.ai plus pasted text. Moving from option 1 to
option 2 costs a re-paste per project and loses nothing on disk, because the hub is
the source of truth and the projects are only doors into it.

The one part that is expensive to reverse is content pasted into instructions: the
Tower cannot edit it, so correcting a rule written there costs a manual re-paste in
every project. That is why instructions hold pointers and non-negotiables only, and
was already acted on in docs/PROJECT_LINK_PROMPT.md.

## Cost of not deciding

No project can be linked, so D-007 and every later global decision reaches exactly
one project. "Dispatched everywhere" stays a word in a document.
