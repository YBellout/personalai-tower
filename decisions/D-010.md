# D-010  Shared library starting scope

    Scope:       global
    State:       answered
    Decided by:  Yassir, 2026-09-20
    Resolves:    D-001 option C
    Supersedes:  nothing

## Context

`_shared` is empty. Filling it with what the platform will need invents consumers
that do not exist yet; filling it with nothing means every project forks its own copy
of the same four things.

## Options

1. **Recommended, and taken.** Four modules that have consumers today: app skeleton,
   atomic storage, paced HTTP client, LLM wrapper with budget. Portal client,
   Postgres helper, Access check and PWA template are named but empty until the mini
   exists.
2. Everything the architecture doc implies, written now. Eight modules, four of them
   with no caller, tested against nothing.
3. Nothing until the second use appears. Purest, and it means the Virtual Closet's
   pace limit, finding VC-F4, gets written locally and extracted later.

## Reversibility

Fully reversible in both directions and cheap in this one: nothing imports `_shared`
yet, so adding or removing a module today costs a file. The second-use rule already
caps the scope, so option 1 cannot quietly grow into option 2.

Naming the four empty modules is the only forward commitment, and a name is free to
change while nothing imports it.

## Cost of not deciding

The paced HTTP client is the fix for VC-F4, carried over from the permission
decision. Without a home it gets written inside the Closet, and the first extraction
happens under pressure rather than by design.
