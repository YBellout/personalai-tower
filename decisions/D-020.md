# D-020  promote.sh owns the registry's version fields, and nothing else shared

    Scope:       global
    State:       answered
    Decided by:  Yassir, 2026-09-21, as amendment (a) when accepting S-016's design
    Supersedes:  nothing. A named exception to D-018's single writer of shared files.

## Context

D-018 makes the control room the only writer of shared files, the registry included.
promote.sh is a tool Yassir double-clicks, and it is the only thing that knows which
version it just put into prod/. S-016's first draft had it write the registry and the
evolution map.

## Options

1. **Recommended, and taken.** promote.sh writes `version.prod` and
   `version.prod_released` in the registry entry of the project it promotes, and
   nothing else in any shared file. The evolution map and every other registry field
   stay the control room's.
2. promote.sh writes nothing shared; it reports the version and the control room
   copies it in. Purer, and it leaves the registry wrong between a promote and the
   control room's next turn, which can be hours.
3. The first draft: promote.sh also closes stories in the evolution map. Rejected, the
   map is judgement, not a mechanical fact.

## Reversibility

High. Two fields, one writer. Moving back to option 2 is one line in promote.sh.

## Cost of not deciding

S-016 would be built against a rule that forbids its own step 7.

## Closes when

The M1 audit confirms no tool or chat other than promote.sh wrote the version fields,
and promote.sh wrote nothing else shared.
