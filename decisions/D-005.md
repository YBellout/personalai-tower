# D-005  "iExecAdmin", the named M1 pilot

    Scope:       control-tower
    State:       answered
    Decided by:  Yassir, 2026-09-20
    Supersedes:  nothing

## Context

Design doc sections 13 and 17 name a project, "iExecAdmin", as the first adoption and
write M1's exit test against it. It appears nowhere else: not under the hub root, not
in the handover, not in any project's memory, and not in the registry.

## Options

1. **Recommended, and taken.** Out of scope. It is not a project this Tower governs.
   M1's exit test is rewritten against the subject D-012 actually names second, AI
   Architecture Tower, and the design doc's sections 13 and 17 are superseded on this
   point by D-012.
2. In scope, location to be supplied. Keeps the design doc intact, and blocks M1 on a
   folder nobody can find.
3. Leave it open. The status quo, which is a milestone whose exit test names a subject
   that does not exist.

## Consequence carried with the pick

AI Architecture Tower is docs-only, and M1's exit test as written assumes a project
with code: break something in dev, watch promote refuse, promote a good change, roll
it back, the app still works. That test cannot run as written against a docs-only
project. So M1 either keeps a code project as the subject of its exit test, or the
exit test is rewritten. That is a real choice and it is not settled by this decision.
It is recorded as D-013 and it is an M1 question, not an M0 one.

## Reversibility

Free. If iExecAdmin turns out to exist, it gets a registry stub and a place in the
D-012 order like any other candidate, and this decision is superseded rather than
edited.

## Cost of not deciding

M1 has no subject and no runnable exit test, so the milestone cannot be declared
passed or failed.
