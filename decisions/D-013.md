# D-013  M1's exit test, and which project it runs against

    Scope:       control-tower
    State:       answered
    Decided by:  Yassir, 2026-09-20
    Supersedes:  nothing. Answers the question D-005 raised.

## Context

M1's exit test is written for a project with code: break something in dev, watch
promote refuse, promote a good change, roll it back, the app still works. D-005 removed
iExecAdmin, and D-012 puts Platform Architecture second, which is docs-only, so the test
had no subject it could run against.

## Options

1. **Recommended, and taken.** The subject is the Tower itself. It has code, the
   heartbeat, and promoting `heartbeat.sh` from `dev/` to `prod/` through `promote.sh`
   is exactly the trigger that closes X-001. M1's exit test and X-001's closure become
   the same event, proved once. Platform Architecture runs alongside as the docs-only
   rehearsal of adoption steps 1 to 8.
2. The Family School Dashboard as the subject. Real code, but the highest-sensitivity
   data in the hub, on the first run of an unproven promote.
3. Rewrite the exit test for docs. Proves adoption, and proves nothing about promote or
   rollback, which is what M1 exists to prove.

## Reversibility

Free until M1 starts. The test text is one row in the design doc's milestone table.

## Cost of not deciding

M1 could be neither passed nor failed.
